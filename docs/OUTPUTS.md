# SimToPC Outputs

## generate

Running:

    simtopc generate config.yml

creates a folder named as the user-defined `mesh_density` parameter
(e.g. `MESH_DENSITY/`) in the repository root.

Inside this folder, one subfolder is created per parameter set defined
by the user:

    MESH_DENSITY/
      test_case_1/
      test_case_2/
      test_case_3/

Each `test_case_i/` folder corresponds to one OpenFOAM simulation case
generated and executed by SimToPC.



## measure

Running:

    simtopc measure config.yml

post-processes each OpenFOAM simulation case generated by the
`generate` command (e.g. `MESH_DENSITY/test_case_i/`) to extract
melt-pool geometrical quantities along the entire scan track.

The measurement workflow proceeds in two main stages:

1. **Track continuity check**  
   Using the known regular mesh spacing, the expected cross-sections
   along the scan track are enumerated.
   If any expected cross-section contains no material cells, the track
   is classified as non-continuous.
   In this case, only a boolean continuity flag is stored and no
   further geometrical analysis is performed for that simulation case.

2. **Per-section geometrical analysis (continuous tracks only)**  
   For continuous tracks, melt-pool geometry is evaluated at each
   cross-section along the track.
   The following quantities are computed:

   - melt pool width (W)
   - melt pool height (H)
   - melt pool depth (D)
   - operational void fraction

The code currently preserves some historical output names, including
`porosity_at_iy`, `row_has_pores`, and `number_of_pores_in_row`. These names
refer to the operational void-fraction calculation used by SimToPC. Fully
enclosed voids correspond to internal pores, whereas surface-connected voids
represent missing material or free-surface depressions in the reconstructed
cross-section.

The computed quantities are written to disk as text or CSV files
associated with each simulation case.

With the cell-based modes (see "Measurement modes" in the README), the same
`cross_sections_statistics.csv` columns are written, and also:

- `metallographic_sections.csv` (`geometry_mode: metallographic`): the
  sections of the window: section index, track coordinate (of the case and from
  the track reference), width, rows below the substrate-top row where the width
  was taken (`width_rows_down`, -1 not measured), depth, height, fill (metal
  fraction of the fusion zone at and below the substrate top), centreline
  surface height, fusion flag and cell counts;
- `metallographic_profile.csv`: the same for every section of the mesh, with
  `in_window` and, with `window_mode: steady_stretch`, `steady_stretch`;
- `metallographic_summary.csv` (next to the configuration file): one row per
  case: scan speed, power, spot size, cell size, track reference, window, steady
  stretch, number of sections, mean, standard deviation and median of the width,
  sections whose width was taken one or two rows lower or not measured, mean
  and standard deviation of the depth, mean and minimum fill, mean and minimum
  centreline surface, continuity;
- `steady_sections.csv` and, with `single_track`,
  `cross_sections_statistics_all_sections.csv` (`steady_sections: true`).




## surrogate

Running:

    simtopc surrogate config.yml

uses the measurements computed by the `measure` command to build
a surrogate model based on a neural network.

The surrogate model is trained using the melt pool quantities
(W, D, H, and the operational void-fraction metric) obtained from the
simulation cases.

The command produces:

- a dataset used for training the surrogate model
- a trained neural network model saved to disk
- files containing training metrics and/or predictions
